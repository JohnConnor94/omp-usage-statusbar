# Usage status-bar extension

## Context
Create an omp extension that keeps a compact remaining-quota summary for every reported account/window in the TUI footer or status line, using the same account reports as `/usage`. Display remaining percentages per window; do not infer absolute token counts. The workspace is empty; Git has no commits or `develop`, so implementation waits for GitFlow bootstrap.

## Approach
1. **Start on a GitFlow feature branch.** Before any working-tree edit, require a clean tree (`git status --short --branch`), a committed baseline (`git log -1 --oneline` succeeds), and local `develop` (`git branch --list develop` returns it). If `feature/usage-statusbar` already exists, stop without reusing or deleting it. If a precondition is missing, stop unless the user explicitly authorizes bootstrap; with approval, commit this plan as the baseline on the current branch and create local `develop`. Then run `git switch -c feature/usage-statusbar develop`. After checks pass, run `git add .gitignore USAGE_STATUS_BAR_EXTENSION_PLAN.md bun.lock package.json src/index.ts src/usage-summary.ts src/usage-summary.test.ts && git commit -m "feat: add usage status-bar extension"`. After verification and commit, run `git switch develop && git merge --no-ff feature/usage-statusbar && git branch -d feature/usage-statusbar`. Do not merge to `master`.
2. **Create the extension package.** Add `package.json` with name `omp-usage-statusbar` and `omp.extensions: ["./src/index.ts"]`. Add `src/index.ts` as the default `ExtensionAPI` factory; load the package with `omp --extension ./` from its root.
3. **Read shared quota reports and publish one status row per account.** In `src/index.ts`, handle only `ctx.mode === "tui" && ctx.agent.kind === "main"`. Fetch with `ctx.modelRegistry.authStorage.usage.reports({ baseUrlResolver, signal })`, using the active `ctx.modelRegistry` and its auth store; do not shell out to `omp usage`, create another auth store, or call provider endpoints directly. Pass `reports ?? []` through `collapseSharedUsageReports()` from `@oh-my-pi/pi-tui/overlays/usage-display` before formatting. Show only accounts with returned quota reports; never infer a missing balance.
   - Read `providers.antigravityEndpoint` through `lookup` from `@oh-my-pi/pi-coding-agent/config/registry` and `findScopedSettings()` from `@oh-my-pi/pi-coding-agent/config/settings` inside `session_start`/`turn_end`. Pass that session `Settings` instance to every refresh, including the timer; do not read process-global `pi.pi.settings`. For `google-antigravity`, map `sandbox` to `https://daily-cloudcode-pa.sandbox.googleapis.com`, `production` to `https://daily-cloudcode-pa.googleapis.com`, and `auto` to `ctx.modelRegistry.getProviderBaseUrl?.(provider)`. Other providers use `ctx.modelRegistry.getProviderBaseUrl?.(provider)`. Keep this resolver identical to `AgentSession.fetchUsageReports()`.
   - Export `formatUsageReports(reports: readonly UsageReport[], resolveUsedFraction: (limit: UsageLimit) => number | undefined, sanitizeText: (text: string) => string): string[]` from `src/usage-summary.ts`. Pass `resolveUsedFraction` from `@oh-my-pi/pi-ai` and `sanitizeText` from `@oh-my-pi/pi-utils`; do not duplicate quota arithmetic. Skip unresolved or non-finite fractions. Compute `round(clamp(1 - usedFraction, 0, 1) * 100)`. Sort by provider, account, then window; group each account's windows on one status row and normalize whitespace after sanitization.
   - Account label precedence: non-empty `metadata.email`, then `metadata.accountId` or `scope.accountId`, then `metadata.projectId` or `scope.projectId`, then `account <report index + 1>`. For non-Codex reports, append a distinct `orgName` or `orgId`; for `openai-codex`, disambiguate duplicate emails with `orgId`, then `accountId`, then report index, and append `planType` when present. Use `limit.label`, adding `window.label` or `scope.windowId` only when the label does not already contain it. Never show credential material or `raw` report data.
   - Use base key `usage-statusbar` for loading/no-data/error messages and indexed `usage-statusbar:<row>` keys for quota rows. The default `statusLine.showHookStatus: true` displays each key as a separate footer row; do not change user settings. A custom status-line preset needs its `status` segment for inline placement.
4. **Refresh and stop safely.** Refresh immediately on `session_start`, after each `turn_end`, and every `60_000` ms through `ctx.setInterval`; prevent overlapping fetches. Keep the existing UsageApi cache authoritative (five-minute TTL with ±25% jitter); never call `invalidate()` on the timer. On `session_shutdown`, abort the in-flight request, clear the timer with `ctx.clearTimer()`, and clear the base and indexed status keys.
5. **Cover formatter behavior.** Add `src/usage-summary.test.ts`; test multiple providers/accounts/windows, one row per account, percent rounding/clamping, unresolved amounts, deterministic order, whitespace sanitization, and empty reports. Keep tests independent of provider/network/UI runtime; inject production `resolveUsedFraction` and `sanitizeText` functions.

## Critical files & anchors

- `packages/coding-agent/src/slash-commands/helpers/usage-report.ts` — `/usage` account/window labels; account helper is private, so implement only the compact rules specified above.
- `packages/ai/src/auth/types.ts` — public `UsageApi.reports()` signature and `UsageReport[] | null` result.

## Verification
- From the extension root, run `bun test` to execute the complete test suite; do not filter individual cases. Fixtures must prove at least two account reports render all windows, correct remaining percentages, deterministic order, and the empty/unresolved/over-limit boundaries.
- After GitFlow preconditions are met, run `omp --extension ./` from the package root in an interactive TUI with at least two authenticated accounts that return quota reports. Before sending a prompt, confirm separate persistent status rows display both accounts and all windows; compare each percentage with `/usage`. Finish a turn and confirm rows remain without duplicate entries. Default footer visibility is sufficient; for a custom status-line preset, include `status` in its segment list.
- Consistency check: inspect `AgentSession.fetchUsageReports()` and grep every `cfgProvidersAntigravityEndpoint` / `google-antigravity` occurrence in the host source; verify the extension's `auto`, `sandbox`, and `production` branches match. Grep the extension package for `usage-statusbar` and `formatUsageReports` to verify base/indexed keys and formatter call sites use the same signature before merging.

## Assumptions & contingencies
- GitFlow bootstrap requires explicit user approval. If a baseline or `develop` branch is missing, stop before editing; do not initialize Git, create an empty commit, or base the feature on `master`.
- Target OMP releases must expose the current `modelRegistry.authStorage.usage.reports()` and extension status APIs (present in current `18.13.2` packages). If unavailable, require an OMP upgrade; do not parse CLI text or add provider-specific polling.
- If two real accounts with quota reports are unavailable, keep the fixture tests but leave the multi-account runtime smoke unverified; do not substitute a mocked UI smoke.

## Implementation record

- User authorized bootstrap. The plan became the baseline on `master`; `develop` and `feature/usage-statusbar` were created before implementation.
- Added the extension, formatter, tests, lockfile, and `node_modules/` ignore rule. OMP dependencies are pinned to `18.13.2`; Bun types are pinned to `1.4.4`.
- Antigravity refreshes use the exact session-scoped `Settings` captured in lifecycle handlers, including timer callbacks.
- `bun test` passed all 4 tests. TypeScript 5.9.3 check passed. OMP RPC loaded the extension successfully.
- The user selected one status row per account after the single row clipped. Final TUI smoke displayed both accounts and all three windows at the observed width; after a turn, the 7-day remaining value changed from 73% to 74% and both rows remained without duplicates.
- Separate `/usage`, extension, and `omp usage --redact` reads showed different Anthropic snapshots. The status uses the report snapshot returned by `UsageApi`; independently fetched snapshots can differ. A single account row may still clip if its labels or window list exceed terminal width.
- A later report-fetch failure preserves the last successful account rows; a first-fetch failure shows `Usage: unavailable`, and an unavailable `reports` API shows `Usage: no quota data`. Lifecycle assertions cover these cases and shutdown cleanup.
