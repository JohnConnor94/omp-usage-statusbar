# Usage status-bar extension

## Context
Create an omp extension that keeps a compact remaining-quota summary for every reported account/window in the TUI footer or status line, using the same account reports as `/usage`. Display remaining percentages per window; do not infer absolute token counts. The workspace is empty; Git has no commits or `develop`, so implementation waits for GitFlow bootstrap.

## Approach
1. **Start on a GitFlow feature branch.** Before any working-tree edit, require a clean tree (`git status --short --branch`), a committed baseline (`git log -1 --oneline` succeeds), and local `develop` (`git branch --list develop` returns it). If `feature/usage-statusbar` already exists, stop without reusing or deleting it. Then run `git switch develop && git switch -c feature/usage-statusbar`. If any precondition is missing, stop without creating files or Git history. After all checks pass, run `git add package.json src/index.ts src/usage-summary.ts src/usage-summary.test.ts && git commit -m "feat: add usage status-bar extension"`. After verification and commit, run `git switch develop && git merge --no-ff feature/usage-statusbar && git branch -d feature/usage-statusbar`. Do not merge to `master`.
2. **Create the extension package.** Add `package.json` with name `omp-usage-statusbar` and `omp.extensions: ["./src/index.ts"]`. Add `src/index.ts` as the default `ExtensionAPI` factory; load the package with `omp --extension ./` from its root.
3. **Read the shared quota reports and publish one status item.** In `src/index.ts`, handle only `ctx.mode === "tui" && ctx.agent.kind === "main"`. Fetch with `ctx.modelRegistry.authStorage.usage.reports({ baseUrlResolver, signal })`, using the active `ctx.modelRegistry` and its auth store; do not shell out to `omp usage`, create another auth store, or call provider endpoints directly. Pass `reports ?? []` through `collapseSharedUsageReports()` from `@oh-my-pi/pi-tui/overlays/usage-display` before formatting. Show only accounts with returned quota reports; never infer a missing balance.
   - Match `/usage` base-URL selection: import `lookup` from `@oh-my-pi/pi-coding-agent/config/registry` and read `lookup("providers.antigravityEndpoint")?.get(pi.pi.settings) ?? "auto"`. For `google-antigravity`, map `sandbox` to `https://daily-cloudcode-pa.sandbox.googleapis.com`, `production` to `https://daily-cloudcode-pa.googleapis.com`, and `auto` to `ctx.modelRegistry.getProviderBaseUrl?.(provider)`. Other providers use `ctx.modelRegistry.getProviderBaseUrl?.(provider)`. Keep this resolver identical to `AgentSession.fetchUsageReports()`.
   - Export `formatUsageReports(reports: readonly UsageReport[], resolveUsedFraction: (limit: UsageLimit) => number | undefined, sanitizeText: (text: string) => string): string` from `src/usage-summary.ts`. Pass `resolveUsedFraction` from `@oh-my-pi/pi-ai` and `sanitizeText` from `@oh-my-pi/pi-utils`; do not duplicate quota arithmetic. Skip unresolved or non-finite fractions. Compute `round(clamp(1 - usedFraction, 0, 1) * 100)` and render each entry as `<provider>/<account> <window> <remaining>%`; sort by provider, account, then window and join entries with ` · `.
   - Account label precedence: non-empty `metadata.email`, then `metadata.accountId` or `scope.accountId`, then `metadata.projectId` or `scope.projectId`, then `account <report index + 1>`. For non-Codex reports, append a distinct `orgName` or `orgId`; for `openai-codex`, disambiguate duplicate emails with `orgId`, then `accountId`, then report index, and append `planType` when present. Use `limit.label`, adding `window.label` or `scope.windowId` only when the label does not already contain it. Never show credential material or `raw` report data.
   - Set status key `usage-statusbar`. On start show `Usage: loading`; if no report has a resolvable limit, show `Usage: no quota data`; on fetch failure show `Usage: unavailable`. A partial report displays available limits. The default `statusLine.showHookStatus: true` makes the item visible in the footer; do not change user settings. A custom status-line preset needs its `status` segment for inline placement.
4. **Refresh and stop safely.** Refresh immediately on `session_start`, after each `turn_end`, and every `60_000` ms through `ctx.setInterval`; prevent overlapping fetches. Keep the existing UsageApi cache authoritative (five-minute TTL with ±25% jitter); never call `invalidate()` on the timer. On `session_shutdown`, abort the in-flight request, clear the timer with `ctx.clearTimer()`, and clear the status with `ctx.ui.setStatus("usage-statusbar", undefined)`.
5. **Cover formatter behavior.** Add `src/usage-summary.test.ts`; test multiple providers/accounts/windows, percent rounding/clamping, unresolved amounts, deterministic order, and empty reports. Keep the test file dependency-free at runtime; pass the production `resolveUsedFraction` and `sanitizeText` functions into the formatter.

## Critical files & anchors
- `packages/coding-agent/src/session/agent-session.ts` — `fetchUsageReports(signal)`; mirror its special Antigravity base-URL resolver.
- `packages/coding-agent/src/slash-commands/helpers/usage-report.ts` — `/usage` account/window labels; account helper is private, so implement only the compact rules specified above.
- `packages/ai/src/auth/types.ts` — public `UsageApi.reports()` signature and `UsageReport[] | null` result.
- `packages/ai/src/usage.ts` — public `UsageReport`, `UsageLimit`, and `resolveUsedFraction()`.

## Verification
- From the extension root, run `bun test` to execute the complete test suite; do not filter individual cases. Fixtures must prove at least two account reports render all windows, correct remaining percentages, deterministic order, and the empty/unresolved/over-limit boundaries.
- After GitFlow preconditions are met, run `omp --extension ./` from the package root in an interactive TUI with at least two authenticated accounts that return quota reports. Before sending a prompt, confirm one persistent status contains both accounts; compare each window percentage with `/usage`. Finish a turn and confirm the status refreshes without duplicate entries. Default footer visibility is sufficient; for a custom status-line preset, include `status` in its segment list.
- Consistency check: inspect `AgentSession.fetchUsageReports()` and grep every `cfgProvidersAntigravityEndpoint` / `google-antigravity` occurrence in the host source; verify the extension's `auto`, `sandbox`, and `production` branches match. Grep the extension package for `usage-statusbar` and `formatUsageReports` to verify one status key and all formatter call sites use the same signature before merging.

## Assumptions & contingencies
- GitFlow bootstrap is user-owned: if a committed baseline and `develop` are still absent, stop before editing; do not initialize Git, create an empty commit, or base the feature on `master`.
- Target OMP releases must expose the current `modelRegistry.authStorage.usage.reports()` and extension status APIs (present in current `18.13.2` packages). If unavailable, require an OMP upgrade; do not parse CLI text or add provider-specific polling.
- If two real accounts with quota reports are unavailable, keep the fixture tests but leave the multi-account runtime smoke unverified; do not substitute a mocked UI smoke.
